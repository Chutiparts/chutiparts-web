# Thai DocOps OS (docbrief) — ฟีเจอร์ที่มีตอนนี้

> One-page summary · อัปเดต 25 ก.ค. 2569 · สถานะ: production + กำลังเข้า dogfood

## 📥 รับเอกสารเข้า → แปลงเป็นข้อมูลพร้อมใช้

- อัปโหลดเอกสาร (รูป/ไฟล์) แล้ว **AI ช่วยอ่านให้อัตโนมัติ**แบบ vision extraction
- **Profile B — บัญชี:** อ่าน header เช่น ผู้ขาย, เลขที่, วันที่, ยอด, VAT, เลขภาษี → ตรวจตามกฎไทย (VAT 7%, checksum เลขภาษี, พ.ศ.→ค.ศ., คำนวณยอด) → ส่งออก Google Sheet
- **Profile A — รับเข้าสต็อก:** อ่านใบส่งของ → แตกเป็นรายการทีละบรรทัด → สร้าง SKU อัตโนมัติ (ต่อเลขรันจริงตามรุ่นรถ) + จัดหมวดหมู่ + ระบุสภาพ → owner เติมราคาขาย/ที่เก็บ → เข้าสต็อกตรงโดยข้าม Sync

## 🗂️ จัดการงานเอกสาร (6 ข้อจาก blueprint)

1. **กล่องงาน (Inbox)** — รวมใบที่ต้องทำตอนนี้ทุก profile: รอตรวจ / รอส่ง / ไม่ผ่าน และเรียงใบที่ค้างนานสุดก่อน
2. **ถังทิ้ง / กู้คืน** — ทิ้งลงถังได้โดยไม่ลบจริง กู้คืนได้เสมอ และไม่มีปุ่มลบถาวรใน UI
3. **ตรวจเอกสารซ้ำ** — จับเนื้อหาซ้ำอัตโนมัติ พร้อมหน้าเทียบ 3 ช่อง โดยให้คนตัดสินเสมอ ไม่มี auto-block
4. **คลังเอกสาร + ค้นหา** — ค้น keyword และ filter ได้ตามประเภท, สถานะ, ผู้ขาย, วันที่, ยอด, และธงซ้ำ พร้อม Activity Timeline รายใบ
5. **Dashboard ต้นทุน** — ดูค่า AI, เวลาที่ประหยัด (โดยประมาณ จากสมมติฐาน baseline), review rate, export success rate และแยกผลตาม Profile A/B
6. **RBAC หลายบทบาท** — owner / reviewer / operator / viewer พร้อม guard ฝั่ง server ทุก action สำคัญ

## 🔒 หลักความปลอดภัยที่ยึด

- ทุกใบผ่านคนตรวจ ไม่มี auto-export
- ไม่ลบข้อมูลถาวรจาก UI และมี audit ผูกผู้ทำจริงทุก action
- แยกสิทธิ์ด้วย env secret โดยไม่ทำ login ใหม่
- export และกู้คืน จำกัด owner เท่านั้น

## 🧭 เมนูแยกตามบทบาท

- **Owner:** เห็นครบทั้งการเงิน / สต็อก / เอกสาร รวมถึงต้นทุน AI และเมนูดูแลระบบ
- **พนักงาน docbrief:** เห็นเฉพาะเมนูที่จำเป็น เช่น กล่องงาน, บัญชี, รับเข้าสต็อก, และคลังเอกสาร ตามแนวคิดแยก owner กับ staff ให้เรียบและปลอดภัย
