## สรุปผู้บริหาร (ฉบับเต็ม)

วันนี้ทำ **roadmap ตาม blueprint "Thai DocOps OS" ครบทั้ง 6 ข้อ** (#1–#6) — ยกระดับ docbrief จาก "เครื่องมืออ่านเอกสาร" เป็น **ระบบ DocOps ครบวงจร** พร้อม workflow, การกู้คืน, ตรวจซ้ำ, ค้นย้อนหลัง, dashboard ผู้บริหาร และสิทธิ์หลายบทบาท

## งานที่เสร็จ (6 ข้อ)

### #1 กล่องงาน (Workflow Inbox) — blueprint §5
- หน้าใหม่ `/ops-x7k2m9/inbox` รวม **"ใบที่ต้องทำตอนนี้"** ทั้งบัญชี + สต็อก ในที่เดียว
- 3 กลุ่ม: รอตรวจ · รอส่ง Sheet · ไม่ผ่าน · เรียงเก่าสุดขึ้นก่อน (ค้างนานสุด)
- แต่ละใบ: ป้ายประเภท · ยอด · เวลาค้าง · ธงเตือน · **ลิงก์ไปหน้าที่ทำงานได้ทันที**

### #2 ถังทิ้ง / กู้คืน (Soft delete) — blueprint §11, §18
- ปุ่ม 🗑 ทุกหน้าเอกสาร → **ทิ้งลงถัง (ไม่ลบจริง)** · หน้า `/trash` มีปุ่ม ↩ กู้คืน
- **ไม่มีปุ่มลบถาวรใน UI** (ตาม §18) · ไฟล์ต้นฉบับ + audit + export trace อยู่ครบ · ทิ้ง/กู้ ลง audit ทุกครั้ง
- DB: migration M10 (คอลัมน์ `deleted_at`)

### #3 ตรวจเอกสารซ้ำ + หน้าเทียบ (possible_duplicate) — blueprint §9, §10, §14
- ตอน AI อ่านเสร็จ → เช็ก **"เนื้อหาซ้ำ"** อัตโนมัติ (ต่างจาก exact-file-dup เดิม)
- คะแนน: เลขที่ตรง (0.4) + ยอดตรง (0.4) + ผู้ขายคล้าย (0.15) + วันที่ใกล้ (0.15) · เกณฑ์ 0.5
- เจอ → ธง **"อาจซ้ำ"** + **หน้าเทียบ 3 ช่อง** (เหตุผล / ใบปัจจุบัน / ใบเดิม) + ปุ่มปลอดภัย: "ยืนยันว่าไม่ซ้ำ" · "เป็นเอกสารซ้ำ → ถังทิ้ง"
- **ไม่ auto-block — คนตัดสินเสมอ** (§14) · DB: migration M11 (`review_metadata`)
- **พิสูจน์กับใบจริง:** ใบส่งของถ่าย 2 มุม (ยอด 38,000 ตรงกัน) → เตือนถูก

### #4 คลังเอกสาร / ค้นหา + Activity Timeline — blueprint §5, §12
- หน้า `/repository` — ค้น keyword + filter: ประเภท · สถานะ · ผู้ขาย · ช่วงวันที่ · ช่วงยอด · เฉพาะที่อาจซ้ำ · ทุก profile ทุกสถานะ
- หน้า detail `/repository/[id]` — ข้อมูลที่ดึงได้ + สถานะส่งออก + **Activity Timeline** (actor / action / เวลา / before→after · แยกไอคอนระบบ vs คน · แปลไทยทุก event)

### #5 Dashboard วัดความคุ้มค่า (เพิ่มเติม) — blueprint §6
- หน้า "ต้นทุน AI" เพิ่ม: **เวลาที่ประหยัด** (จำนวนใบ × นาที/ใบ) · **แยก Profile บัญชี/สต็อก** · **% ต้องตรวจพิเศษ (review rate)** · **% ส่งออกสำเร็จ (export success rate)**
- (ของเดิม: ค่า AI วันนี้/7วัน/30วัน · เฉลี่ย/ใบ vs cap · งานค้าง · กราฟ 7 วัน)

### #6 RBAC หลายบทบาท — blueprint §7, §18
- 4 บทบาท: **owner / reviewer / operator / viewer** พร้อมตารางสิทธิ์
- **guard ฝั่ง server ทุก action สำคัญ** (upload/extract/edit/confirm/export/reject/trash/restore/dedup) — ไม่พึ่งการซ่อนปุ่ม UI (§7)
- export + restore = **owner เท่านั้น** · audit ผูกผู้ทำจริง
- **lean:** ไม่ทำ login ใหม่ (§18) — แยกบทบาทด้วยรหัสผ่าน env (`OPS_REVIEWER_SECRET` ฯลฯ)
- **backward-compatible:** ไม่ตั้ง role secret = owner-only เหมือนเดิมเป๊ะ
