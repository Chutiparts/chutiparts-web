# BRIEF ส่ง Claude Code — Extraction fixes สำหรับ bulk-intake (โน้ตจีน + ราคายอดรวม)
เป้า: ให้ตัวอ่านบิลป้อนข้อมูลเข้าฟอร์ม intake ได้ครบพอ → คนเหลือแค่ "แตะยืนยัน" แทนพิมพ์ทุกช่อง
ไฟล์: `lib/docbrief-extract-stock.ts` (ไฟล์เดียว) · main ล่าสุด
**ขอบเขต: แก้ SYSTEM_PROMPT + post-process (`assessLine`) เท่านั้น · ห้ามแตะ trigger/confirm/RLS/SKU-assign/DB write**

## ที่มา (ทดสอบบิลจริงแล้ว — หน้า 泰國 19 แถว)
ผลเทส: ✅ segment 19/19 · ✅ AI อ่านจีนแม่น (空氣流量計/節氣門 ถูก) · ✅ confidence ต่ำ (30-50%) ซื่อสัตย์ · ✅ SKU auto
แต่เจอ 2 คอขวดที่ทำให้คนยังต้องพิมพ์เยอะ:
1. **ชื่อออกมาเป็นจีน** (頭尾燈, 拉手) แต่คลังชื่อในสต็อกเป็น**ไทย** → dropdown "คล้ายของเดิม" match ไม่เจอเลย → พิมพ์ไทยเองทั้ง 19 แถว
2. **ช่องต้นทุนว่าง** เพราะโน้ตเขียน "ราคาเดียว/บรรทัด" ไม่มีจำนวน · AI ใส่เลขไว้ที่ `amount` แต่ `unit_price`=null + `qty`=null → ต้นทุน/ชิ้นว่าง → **ปุ่ม ×2/×2.5/×3 ไม่โผล่** (มันคำนวณจากต้นทุน) → พิมพ์ราคาขายเองอีก

## Fix A — part_name ออกมาเป็นไทย (แก้ SYSTEM_PROMPT)
ปัญหาปัจจุบัน: prompt สั่ง *"part_name: คัดลอกตามที่เขียนเป๊ะ ๆ"* → ได้จีนตรงตัว → ไม่ match คลังไทย

เปลี่ยนกฎ part_name เป็น (คงเจตนาเดิม "ไม่แต่งของที่ไม่มี" ไว้):
- **อ่านชื่ออะไหล่แล้วแปล/ทับศัพท์เป็น "ชื่ออะไหล่ภาษาไทยมาตรฐานของช่างไทย"** — เช่น 空氣流量計→"วัดอากาศ (มาตรวัดอากาศ)", 節氣門→"ลิ้นปีกผีเสื้อ", 拉手/把手→"มือจับ", 尾灯/尾燈→"ไฟท้าย", 大燈→"ไฟหน้า", 風箱→"ตู้แอร์", 儀表板→"เรือนไมล์", 出風口→"ช่องแอร์"
- **ถ้าต้นฉบับเป็นไทยอยู่แล้ว → คงไว้** (แปลเฉพาะเมื่อเป็นจีน/อังกฤษ)
- **รหัสรุ่น (W140/S600/R129) แยกไปที่ `car_model` เหมือนเดิม** — `part_name` เอาเฉพาะชื่ออะไหล่ (ไม่ต้องมี W-code นำ) เพื่อให้ fuzzy match คลังไทยตรง
- **อ่านไม่ออก/ไม่มั่นใจว่าแปลถูก → ยังใส่ค่าที่เดาได้ แต่ตั้ง confidence ต่ำ** (คนตรวจอยู่แล้ว · ไม่มี auto-post) · ห้ามทิ้ง null ถ้าพออ่านจีนออก
- **ห้ามแต่งของที่ไม่มีในเอกสาร** (กฎเดิม คงไว้)

## Fix B — บรรทัดราคาเดียว: เติมจำนวน=1 + ต้นทุนจาก amount (post-process ใน `assessLine`)
ทำแบบ deterministic ใน `assessLine` (ไม่พึ่ง prompt) — หลังอ่านมาแล้ว ก่อนคืนค่า:
- **ถ้า `qty == null` → default `qty = 1`** (โน้ตลอตแบบนี้ ไม่เขียนจำนวน = 1 ชิ้น เป็นปกติ) · แต่ **ตั้ง flag ใหม่ `qty_defaulted`** ให้คนเห็นว่าเป็นค่าเดา (ไม่ใช่จากเอกสาร)
- **ถ้า `unit_price == null` และ `amount != null` → `unit_price = amount / qty`** (qty ที่ default แล้ว) → ต้นทุน/ชิ้นเต็ม → ปุ่ม ×N โผล่
  - ถ้าหาร amount/qty ไม่ลงตัวเป๊ะ ก็ใส่ได้ (ปัดทศนิยม) + flag `unit_price_derived`
- **arithmetic check เดิมคงไว้** (qty×unit_price≈amount) — หลังเติมแล้วมันจะ ok เอง
- **อย่าแตะ amount ที่มาจากเอกสารจริง** (ถ้ามีทั้ง qty+unit_price+amount ครบแล้ว = ไม่ยุ่ง)

เพิ่ม flag ใหม่ 2 ตัวใน FLAG_TH map ของหน้า inbox/stock-intake ด้วย (ให้แสดงเป็นไทย):
- `qty_defaulted` → "จำนวนเดา (1)" · `unit_price_derived` → "ต้นทุนคำนวณจากยอดรวม"
(ถ้าเพิ่ม flag แล้วต้องเติมใน FLAG_TH ทั้ง `inbox/page.tsx` + `StockIntakeClient.tsx` เพื่อไม่ให้ธงโชว์เป็น key ดิบ)

## กันพลาด
- แตะ **`lib/docbrief-extract-stock.ts` เป็นหลัก** (+ FLAG_TH 2 จุดถ้าเพิ่ม flag) · **ห้ามแตะ** `extractStockDocument` flow เขียน DB, `assignSkusForDocument`, `confirmStockDocument`, trigger, RLS
- Fix A = เปลี่ยนข้อความ prompt เท่านั้น · Fix B = logic ใน assessLine (pure function) ไม่ยิง DB
- **ไม่ auto-post** — ทุกบรรทัดยังผ่านคนตรวจเหมือนเดิม (คงหลักการ §9 "ชื่อลายมือต้องผ่านตา owner")
- default qty=1 + unit_price_derived **ต้องติด flag** เสมอ (คนต้องรู้ว่าเป็นค่าเดา ไม่ใช่จากเอกสาร)
- ไม่เปลี่ยน schema fields (qty/part_name/unit_price/amount/car_model/confidence คงเดิม) · flag เพิ่มใน review_flags array เดิม

## Acceptance (รันบิลหน้า 泰國 ใบเดิมซ้ำ แล้วเทียบ)
1. ชื่ออะไหล่ออกมาเป็น**ไทย** (空氣流量計→"วัดอากาศ" ฯลฯ) · car_model ยังแยกถูก
2. **dropdown "คล้ายของเดิม" เริ่ม match** กับคลังไทย (ถ้าร้านมีชื่อคล้ายในสต็อก)
3. บรรทัดที่มีราคาเดียว → **ต้นทุน/ชิ้นเต็ม** + **ปุ่ม ×2/×2.5/×3 โผล่**
4. บรรทัดไม่มีจำนวน → qty=1 + ธง "จำนวนเดา (1)" · ต้นทุนจาก amount → ธง "ต้นทุนคำนวณจากยอดรวม"
5. ไม่มีบรรทัดไหน auto-post · confidence ต่ำยังโชว์ · tsc/lint สะอาด
