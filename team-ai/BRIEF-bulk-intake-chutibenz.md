# BRIEF ส่ง Claude Code — Bulk-lot stock intake: "AI เติมโครง + คนแตะเลือกชื่อ"
เป้า: ทำหน้า review ของ stock intake ให้ "รับลอตใหญ่จบเร็ว" โดยโฟกัสแรงคนไปที่ช่องเดียวที่ AI ทำไม่ได้ = ชื่ออะไหล่
แตะไฟล์: `app/ops-x7k2m9/stock-intake/StockIntakeClient.tsx` + `app/ops-x7k2m9/stock-intake/page.tsx` · main ล่าสุด
**ขอบเขต: ปรับ UI หน้า review + data ที่ป้อนเข้า UI เท่านั้น · ห้ามแตะ extraction · ห้ามแตะ `confirmStockDocument` (idempotent อยู่แล้ว) · ห้ามแตะ RLS/trigger**

## ที่มา (วัดจากบิลจริงแล้ว — อย่าข้าม)
บิลลอตใหญ่ ChutiBenz = **โน้ตลายมือ** (จดตอนไปซื้อ · ≤20 รายการ/หน้า) วัดจริงกับหลายใบพบว่า AI (claude-opus-4-8 ตัวเดิม):
- **รุ่น (W124/W140/R129/S600) → อ่านแม่นเกือบหมด** (รหัสมาตรฐาน)
- **ราคา (เลขบาท) → อ่านได้ดี** · **จำนวน (×2/×5) → พอได้**
- **ชื่ออะไหล่ (ลายมือไทย) → confidence ต่ำเกือบทั้งแถว** ← จุดเดียวที่พัง
เดิมทุกช่องเป็น input พิมพ์มือเท่ากันหมด + ต้องพิมพ์ราคาขายเอง → ตรวจลอต 20 แถวเหนื่อย → คนเลิกใช้ (5/10 ใบค้าง pending_review) นี่คือรากปัญหาที่ต้องแก้

## หลักการ (confidence-driven)
AI เติมช่องที่มั่นใจให้ล่วงหน้า (รุ่น→chassis/SKU · จำนวน · ต้นทุน) → คน**แค่แตะเลือกชื่อ + ใส่ราคาขาย + ที่เก็บ** ไม่ต้องพิมพ์ชื่อ/เลขซ้ำ
- ราคาในโน้ต = **ต้นทุน (unit_price)** ยืนยันแล้ว
- เจ้าของเลือก **กรอกครบทุกช่องตอนรับ** (ไม่ทำ 2 รอบ · กันใบค้างครึ่งๆ) → หน้านี้ต้องทำให้ "ครบ" ไว แต่ไม่ใช่ "พิมพ์เยอะ"

## สิ่งที่ต้องทำ (แปลง `LineForm` เป็น smart form)
ต่อ 1 บรรทัด — AI pre-fill + คนแตะ:

1. **ชื่ออะไหล่ (`part_name`) → combobox แตะเลือก** (หัวใจ)
   - default = ชื่อที่ AI เดา (ต่อให้ conf ต่ำ) · ใต้ช่องโชว์ **ตัวเลือกที่ใกล้ที่สุดจากของเดิม** ให้แตะ
   - แหล่งลิสต์ = **distinct `part_name` จาก `stock_records`** (คลังคำจริงของร้าน · ส่งจาก `page.tsx`) — reuse logic เดียวกับ `warnByLine` (fuzzy similarity) ที่มีอยู่แล้ว ขยายจาก "เตือน" เป็น "เลือกได้"
   - มี **ตัวกรองหมวด** จาก `PARTS_CATEGORIES` (16 หมวด ใน `lib/constants.ts`) ช่วยหาเร็ว
   - พิมพ์ชื่อใหม่ได้ (ของที่ไม่เคยมี) → กลายเป็นคำในลิสต์รอบหน้าเอง
   - คงกรอบเตือน `warn`/`name_uncertain` เดิมไว้ (ชื่อ conf ต่ำ = ไฮไลต์ให้คนดูก่อน)

2. **ราคาตั้งขาย (`set_price`) → input + ปุ่มช่วยคูณต้นทุน**
   - ปุ่มเร็ว **×2 / ×2.5 / ×3** ของ `unit_price` (แตะแล้วเติมเลขให้ · แก้ต่อได้) — กันพิมพ์เลขทุกแถว
   - ยังเป็น required เดิม (ต้องมีก่อน confirm)

3. **SKU (`sku`) → auto-fill ตอนโหลด** (ไม่ต้องรอกดปุ่ม)
   - ใช้ `autoSku` เดิม: chassis จาก `car_model` (W140→140) → เลขรันถัดไป · เติมให้ทุกแถวอัตโนมัติ · แก้เองได้
   - หมวดพิเศษ (เช่น 140-AC) คงพฤติกรรม prefix เดิม

4. **ที่เก็บ (`location`) → quick-pick** จาก distinct `location` เดิม (datalist/ปุ่มล่าสุด) + พิมพ์เองได้

5. **สภาพ (`condition`)** → default "มือสอง" · ถ้าโน้ต/AI จับคำ "ของใหม่/金新" ได้ → เดา "ใหม่" ให้

6. **จำนวน / ต้นทุน** → pre-fill จาก AI (แก้ได้) · แสดงแบบ compact (มั่นใจสูง ไม่ต้องเด่น)

## Layout (โฟกัสสายตาไปที่งานจริง)
- แถวที่ field โครงสร้าง (รุ่น/จำนวน/ต้นทุน/SKU) มั่นใจสูง → แสดง compact/จาง
- **ช่องชื่อ = เด่นสุด** (คือสิ่งที่คนต้องทำ) · ราคาขาย/ที่เก็บ = รอง
- บรรทัดติดธง (`name_missing`/`arithmetic_mismatch`/`name_uncertain`) → ลอยขึ้นบน/มาร์คให้เห็นก่อน
- มี counter "เหลือ N แถวที่ยังไม่ครบ (ชื่อ/ราคาขาย/ที่เก็บ)" ให้รู้ว่าใกล้กด confirm ได้yหรือยัง (ใช้ REQ เดิมใน `ConfirmFooter`)

## Data (เพิ่มใน page.tsx — server)
- ดึง **distinct `part_name`** (ตัด null/ว่าง · limit สมเหตุผล เช่น 500 ล่าสุด/ที่ใช้บ่อย) ส่งเป็น prop `nameOptions`
- ดึง **distinct `location`** ส่งเป็น prop `locationOptions`
- ทั้งคู่ count/select เบา ๆ · fail → ส่ง [] (ห้ามทำหน้าล่ม)

## กันพลาด (สำคัญ)
- **ห้ามแตะ `confirmStockDocument`** — มันคือ path เข้าสต็อกจริง idempotent 3 ชั้น (สร้าง row qty=0 → received movement + unique index) การแก้จะเสี่ยงนับเบิ้ล
- ทุก field ที่แตะ = ยังต้องผ่าน `saveLine` เดิม (เก็บทีละช่อง) · การ confirm ใช้ REQ เดิม (sku·part_name·qty·unit_price·set_price·location)
- combobox เลือกชื่อ = ต้อง set ค่าเข้า input `part_name` ตัวเดิม (server action ไม่เปลี่ยน schema)
- ราคาขายปุ่มคูณ = client เติมค่าเฉย ๆ ต้อง trigger `saveLine` เหมือนพิมพ์มือ
- ห้ามลบ field เดิม (category/oem/note) — แค่จัดลำดับความเด่น
- new part name (ไม่เคยมี) ต้องบันทึกได้ปกติ (ไม่บังคับต้องอยู่ในลิสต์)
- ลอตเล็กไม่เกี่ยว — เข้าทาง "รับเข้าสต็อก/เพิ่มสินค้า" เดิม (ห้ามยัดลอตเล็กมาทางนี้)

## Acceptance
1. เปิดใบ pending_review ที่มาจากรูปลอต → ทุกแถว pre-fill รุ่น/จำนวน/ต้นทุน/SKU อัตโนมัติ · ช่องชื่อ default = AI เดา + มีตัวเลือกใกล้เคียงให้แตะ
2. แตะเลือกชื่อจากของเดิมได้ (ไม่ต้องพิมพ์) · พิมพ์ชื่อใหม่ก็ได้
3. ปุ่ม ×2/×2.5/×3 เติมราคาขายจากต้นทุนได้ · แก้ต่อได้
4. ที่เก็บ quick-pick จากของเดิมได้
5. กรอกครบทุกแถว → กด confirm → เข้าสต็อกผ่าน received movement (ไม่นับเบิ้ล · reuse confirmStockDocument)
6. บรรทัดชื่อ conf ต่ำ/ติดธง เด่นกว่าบรรทัดปกติ · counter บอกจำนวนแถวที่ยังไม่ครบ
7. tsc/lint สะอาด · แตะ 2 ไฟล์

## Builder review focus
- reuse ของเดิมจริง (warnByLine fuzzy · autoSku · confirmStock · saveLine) ไม่เขียนใหม่ทับ
- nameOptions มาจาก stock_records จริง (ไม่ประดิษฐ์คำเอง)
- confirm ยัง idempotent (ไม่นับเบิ้ล) · REQ ครบเหมือนเดิม
- ปุ่มคูณ/combobox trigger saveLine ถูกต้อง (ค่าเข้า DB จริง ไม่ใช่แค่ค่าบนจอ)
- perf: distinct query เบา · หน้าไม่ช้าลงตอนลอต 20 แถว
